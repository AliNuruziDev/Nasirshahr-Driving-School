# سامانه آموزشگاه رانندگی نصیرشهر — نسخه ۰.۹

وب‌اپلیکیشن فارسی و راست‌چین برای سه نقش هنرجو، مربی و مدیریت. این نسخه شامل پرونده الکترونیکی هنرجو از ثبت‌نام تا پایان آموزش است.

## اجرای محلی
1. ZIP را استخراج کنید.
2. پوشه را در VS Code باز کنید.
3. با Live Server یا یک وب‌سرور محلی اجرا کنید (برای PWA از `localhost` یا HTTPS استفاده کنید).
4. در صفحه ورود، نقش نمایشی موردنظر را انتخاب کنید. ورود این نسخه آزمایشی است و احراز هویت واقعی ندارد.

## به‌روزرسانی رابط کاربری نسخه ۰.۶
- آیکون‌های اختصاصی و کامل‌تر برای اقدام‌های پرتکرار، تقویم، وضعیت، تماس، امنیت و آموزش.
- فونت Noto Sans Arabic نیز در کنار Vazirmatn از Google Fonts درخواست می‌شود؛ انتخاب فونت از تنظیمات قابل تغییر است.
- فونت رابط کاربری با اولویت Vazirmatn و fallbackهای Noto Sans Arabic و Tahoma؛ فونت از Google Fonts دریافت می‌شود و در صورت عدم دسترسی، فونت جایگزین دستگاه استفاده می‌شود.
- داشبوردهای تفکیک‌شده و غنی‌تر برای هنرجو، مربی و مدیریت.
- مرکز یادگیری و آزمون تمرینی نمونه، تقویم دقیق‌تر، گزارش‌های نمونه و تنظیمات ظاهری.
- ویرایش نمایشی پروفایل، اعلان‌ها، فرم افزودن هنرجو و مربی، و فرم برنامه‌ریزی جلسه.
- ثبت هنرجوی جدید در IndexedDB محلی و مسیر آماده `POST /students` برای بک‌اند.
- انیمیشن ورود ملایم، بازخورد hover/focus و پشتیبانی از تنظیم کاهش حرکت سیستم.


## بازطراحی صفحه ورود نسخه ۰.۶
- صفحه ورود با هویت بصری سرمه‌ای و طلایی آموزشگاه بازطراحی شد؛ هیچ تم رنگی جدیدی اضافه نشده است.
- بخش معرفی آموزشگاه با مسیر تصویری CSS/SVG، نقاط مرحله‌ای و حرکت‌های ملایم جایگزین تصویر خارجی شده است.
- انتخاب نقش هنرجو، مربی و مدیریت به کارت‌های توصیفی با وضعیت انتخاب و ویژگی‌های دسترس‌پذیری تبدیل شد.
- ورودی نام دارای حالت فوکوس، آیکون، متن راهنما و placeholder است؛ نام قبلی ذخیره‌شده در مرورگر در صورت وجود بازیابی می‌شود.
- انیمیشن‌های صفحه ورود و کارت‌ها به تنظیم کاهش حرکت سیستم احترام می‌گذارند.
- عملکرد ورود آزمایشی و مسیرهای داخلی پروژه حفظ شده‌اند؛ احراز هویت واقعی در این نسخه اضافه نشده است.

## بهبود ظاهری ورودی صفحه ورود نسخه ۰.۱۰
- ورودی شناسه ورود با قاب بزرگ‌تر، آیکون اختصاصی، نشان ID و حالت فوکوس طلایی بازطراحی شد.
- عنوان، راهنما و placeholder برای هنرجو، مربی و مدیریت متناسب با نقش انتخاب‌شده تغییر می‌کنند.
- ورود آزمایشی و منطق جست‌وجوی قبلی حفظ شده است؛ این تغییر ظاهر ورودی را بهبود می‌دهد و احراز هویت واقعی اضافه نمی‌کند.
- نسخه کش Service Worker برای دریافت فایل‌های جدید هنگام انتشار به‌روزرسانی شد.

## به‌روزرسانی رابط بارگذاری مدارک

- ناحیه بارگذاری با قابلیت انتخاب فایل از دستگاه یا کشیدن و رهاکردن فایل
- پیش‌نمایش تصویر و نمایش مشخصات فایل پیش از ثبت
- امکان حذف فایل انتخاب‌شده یا انتخاب فایل جایگزین
- کارت‌های حرفه‌ای برای مدارک اولیه هنگام ثبت‌نام هنرجو
- اعتبارسنجی نوع و حجم فایل (PDF، JPG، PNG و WebP تا ۱۲ مگابایت)
- هماهنگ با تم روشن و تاریک و صفحه‌نمایش موبایل

## امکانات موجود
- پنل‌های واکنش‌گرا برای هنرجو، مربی و مدیریت.
- پرونده الکترونیکی یکپارچه با شناسه و گردش کار.
- مراحل پرونده: ثبت اولیه، تکمیل مدارک، ثبت قرارداد، آموزش، آزمون آیین‌نامه، آزمون عملی، پایان آموزش و بایگانی.
- ثبت و ویرایش مشخصات پایه پرونده.
- ثبت قرارداد و وضعیت امضا.
- ثبت پرداخت با مبلغ تومانی، تاریخ، روش و شماره پیگیری.
- ثبت جلسات عملی با مربی، موضوع، مدت، حضور و گزارش آموزشی.
- ثبت آزمون آیین‌نامه و عملی، نمره، نوبت و نتیجه.
- ثبت نتیجه نهایی و شماره گواهینامه.
- اسناد و مدارک فایل‌محور، بایگانی و بازیابی (PDF/JPG/PNG/WebP تا ۱۲ مگابایت در حالت محلی).
- خط زمانی پرونده و ردپای عملیات.
- لایه داده مستقل `NasirData` با Local IndexedDB adapter و REST API adapter.
- مهاجرت IndexedDB از نسخه ۱ به ۲ با حفظ storeهای قبلی.
- طرح پایگاه داده در `backend/migrations` و قرارداد API در `backend/API_CONTRACT.md`.

## نکته حیاتی: داده محلی یا بک‌اند واقعی
در `config.js` حالت پیش‌فرض `mode: 'local'` است. تمام فایل‌ها و اطلاعات در مرورگر همان دستگاه ذخیره می‌شوند؛ این نسخه بایگانی مرکزی، احراز هویت یا پشتیبان‌گیری سروری ایجاد نمی‌کند. مرورگر ممکن است داده را پاک کند. اطلاعات نمونه‌اند. **مدارک هویتی واقعی، پرونده پزشکی یا اطلاعات حساس را تا زمان راه‌اندازی بک‌اند امن وارد نکنید.**

## اتصال بک‌اند در آینده
در `config.js` تنظیم کنید:
```js
window.NASIR_APP_CONFIG = {
  mode: 'api',
  apiBaseUrl: 'https://YOUR-DOMAIN.example/api/v1'
};
```
سرور باید APIهای تعریف‌شده در `backend/API_CONTRACT.md` را پیاده‌سازی کند. صرف تغییر این تنظیم، بک‌اند را ایجاد نمی‌کند و داده‌های IndexedDB را نیز خودکار منتقل نمی‌کند. برای مهاجرت باید ابزار import کنترل‌شده و احراز هویت‌شده ساخته شود.

## پایگاه داده
- `001_initial_schema.sql`: کاربران، هنرجو، مربی، ثبت‌نام، جلسات، اسناد، نسخه‌های اسناد، پرداخت‌های پایه و اطلاعیه‌ها.
- `002_complete_student_case_file.sql`: مشخصات تکمیلی پرونده، قراردادها، گزارش جلسات عملی، آزمون‌ها، نتیجه نهایی، خط زمانی و گزارش ممیزی.

فایل‌ها باید در فضای ذخیره‌سازی خصوصی (S3-compatible یا مشابه) نگهداری شوند؛ خود فایل نباید در پوشه عمومی سایت یا مستقیماً در PostgreSQL ذخیره شود.

## کنترل‌های لازم پیش از استفاده واقعی
1. احراز هویت واقعی و کنترل دسترسی سمت سرور برای هر درخواست.
2. اجازه دسترسی هنرجو فقط به پرونده خودش؛ مربی فقط به هنرجویان تخصیص‌یافته؛ مدیر بر اساس مجوز.
3. رمزنگاری در انتقال و ذخیره، لینک دانلود امضاشده کوتاه‌مدت، ثبت ممیزی و اسکن بدافزار.
4. پشتیبان‌گیری رمزنگاری‌شده از دیتابیس و فایل‌ها و آزمون بازیابی.
5. تعیین مهلت نگهداری، حذف، دسترسی قانونی و سیاست مالی توسط آموزشگاه.
6. برای پرداخت آنلاین، تأیید تراکنش فقط از طریق درگاه/وب‌هوک سرور؛ نه مقدار فرم مرورگر.
7. تست نفوذ و بازبینی حقوقی/عملیاتی قبل از ورود اطلاعات واقعی.

## ساختار اصلی
- `index.html`: پوسته و نقاط ورود رابط
- `styles.css`: طراحی واکنش‌گرا
- `app.js`: رابط، صفحات و تعاملات
- `data-layer.js`: لایه ذخیره‌سازی و قراردادهای API
- `config.js`: انتخاب local یا api
- `sw.js`, `manifest.webmanifest`: پوسته PWA
- `backend/`: مهاجرت‌های SQL و قرارداد API

## تست سریع قرارداد API
با Node.js نسخه ۱۸ یا جدیدتر می‌توانید مسیرهای REST adapter را با پاسخ‌های ساختگی بررسی کنید:
```bash
node tests/api-adapter-smoke.mjs
node tests/ui-smoke.mjs
```
تست API مسیرهای مورد انتظار REST adapter را بررسی می‌کند و تست UI رندر داشبوردهای نقش‌ها و صفحات اصلی را با DOM آزمایشی کنترل می‌کند؛ هیچ‌کدام جایگزین تست واقعی مرورگر، بک‌اند، امنیت یا IndexedDB نیستند.


## نکات نسخه آزمایشی ۰.۶
- فونت‌های Vazirmatn و Noto Sans Arabic از Google Fonts بارگیری می‌شوند؛ اگر شبکه در دسترس نباشد، فونت‌های موجود روی دستگاه مانند Tahoma استفاده می‌شوند. این تغییر فقط روی وب‌اپ است و فونت سیستم‌عامل دستگاه را عوض نمی‌کند.
- فرم افزودن هنرجو در حالت محلی یک پرونده آزمایشی در IndexedDB می‌سازد. در حالت API مسیر `POST /students` باید توسط بک‌اند امن پیاده‌سازی شود.
- جلسات جدید، پروفایل نمایشی و تنظیمات ظاهری در LocalStorage همین مرورگر نگهداری می‌شوند؛ این موارد هنوز به API مرکزی متصل نیستند.
- بخش آزمون دارای چند سؤال عمومی صرفاً نمایشی است و جایگزین بانک سؤالات رسمی یا منبع حقوقی آیین‌نامه نیست.
- اعداد داشبورد و گزارش‌های مدیریتی داده‌های ساختگی برای تست ظاهر هستند.


## نسخه ۰.۷ — پنل ثبت‌نام و مدیریت مالی
- فرم ثبت‌نام کامل هنرجو با مشخصات هویتی، چند شماره تماس، نام سرپرست، نشانی استان/شهر/محله، کد پستی، دوره و تاریخ ثبت‌نام.
- ثبت مبلغ کل شهریه توافق‌شده و دریافتی اولیه؛ مبلغ اولیه به‌عنوان رکورد پرداخت مستقل به پرونده افزوده می‌شود.
- ایجاد قرارداد اولیه به‌صورت پیش‌نویس، زمانی که مبلغ شهریه وارد شده باشد.
- بارگذاری اختیاری مدارک اولیه (کارت ملی، شناسنامه، عکس پرسنلی، مدرک پزشکی در صورت نیاز و سایر) در پرونده تازه‌ساخته‌شده. هر فایل از اعتبارسنجی نوع و سقف ۱۲ مگابایت در لایه داده عبور می‌کند.
- فهرست هنرجویان شامل نشانی خلاصه، تماس، دوره، وضعیت و شهریه؛ جست‌وجو و خروجی CSV.
- صفحه امور مالی مدیریت، مبلغ شهریه، دریافت‌های ثبت‌شده، مانده و پرونده‌های دارای بدهی را از داده‌های پرونده جمع می‌کند و دریافت جدید به پرونده متصل می‌سازد.
- بخش مشخصات پرونده، فیلدهای آدرس و تماس تکمیلی را ویرایش می‌کند.
- پایگاه داده آینده با migration `003_student_intake_finance_contact.sql` توسعه یافته است.

## هشدار اطلاعات واقعی
این نسخه برای تست محلی است. IndexedDB فقط روی همین مرورگر/دستگاه است و امنیت، دسترسی چندکاربره یا پشتیبان‌گیری سروری فراهم نمی‌کند. مدارک هویتی، آدرس و اطلاعات مالی واقعی را تا راه‌اندازی احراز هویت، کنترل دسترسی سرور، فضای فایل خصوصی، رمزنگاری و پشتیبان‌گیری وارد نکنید.


## راهنمای سریع پنل مدیریت ۰.۷
1. در صفحه ورود، نقش «مدیریت» را انتخاب کنید و با نام نمایشی وارد شوید.
2. از منو «مدیریت هنرجویان» را باز کرده و «ثبت هنرجوی جدید» را بزنید.
3. مشخصات، شماره‌های تماس، نشانی، دوره، شهریه توافق‌شده و مبلغ دریافتی اولیه را وارد کنید.
4. در صورت نیاز، فایل‌های کارت ملی، شناسنامه، عکس پرسنلی، مدرک پزشکی (در صورت نیاز) و سایر مدارک را پیوست کنید.
5. پس از ثبت، از دکمه «پرونده» به پرونده کامل بروید؛ اسناد، قرارداد اولیه، پرداخت و گردش پرونده در همان‌جا قرار می‌گیرند.
6. از منوی «امور مالی» مبلغ شهریه، دریافتی، مانده هر پرونده و آخرین دریافت‌ها را ببینید؛ با «ثبت دریافت جدید» پرداخت بعدی را به پرونده هنرجو متصل کنید.
7. از فهرست هنرجویان امکان جست‌وجو و خروجی CSV اطلاعات ثبت‌نام وجود دارد.

**محدودیت تست:** داده‌ها روی همان مرورگر ذخیره می‌شوند. برای چند کاربر هم‌زمان، دسترسی از چند دستگاه، نگهداری امن مدارک و پشتیبان‌گیری، باید بک‌اند و احراز هویت واقعی راه‌اندازی شود.


## نسخه ۰.۸ — تفکیک فضای کاری هنرجو، مربی و مدیریت

### هنرجو
- درخواست ثبت‌نام اولیه از خود صفحه ورود در دسترس است.
- بعد از ساخت پرونده آزمایشی، هنرجو فقط پرونده، اسناد، برنامه جلسات، آموزش آیین‌نامه و خلاصه مالی خودش را می‌بیند.
- هنرجو می‌تواند اعلام پرداخت/ارسال رسید کند؛ این مورد به‌عنوان «در انتظار تأیید» ثبت می‌شود و تا تأیید مدیریت به جمع دریافتی افزوده نمی‌شود.
- زمان‌بندی جلسه توسط مدیریت انجام می‌شود؛ هنرجو فقط جلسه‌های تخصیص‌یافته به خودش را می‌بیند.

### مربی
- منوهای مربی فقط شامل داشبورد، برنامه روزانه خودش، هنرجویان تحت آموزش خودش، گزارش جلسات خودش، اطلاعیه‌ها و پروفایل است.
- فهرست هنرجویان از تخصیص جلسات استخراج می‌شود؛ مربی مدارک هویتی، نشانی کامل، قرارداد، شهریه یا پرداخت‌ها را نمی‌بیند.
- مربی فقط برای هنرجویان تخصیص‌یافته می‌تواند گزارش جلسه، حضور و نکات آموزشی ثبت کند.
- برنامه‌ریزی/تخصیص زمان جلسات فقط در اختیار مدیریت است.

### مدیریت
- مدیریت به فهرست کل هنرجویان و مربیان، پرونده‌ها، بایگانی اسناد، امور مالی، برنامه‌ریزی جلسات و گزارش‌های آموزشگاه دسترسی دارد.
- مدیر می‌تواند هنرجو را به مربی و زمان مشخص تخصیص دهد؛ همان جلسه در برنامه هنرجو و مربی مربوط نمایش داده می‌شود.
- درخواست‌های پرداخت هنرجویان تا زمان تأیید مدیر در وضعیت معلق باقی می‌مانند.

### روش تست نقش‌ها
- هنرجوهای نمونه: «آرمان رضایی»، «نگار محمدی»، «پارسا کریمی» و «هانیه مرادی» (با نام، شماره پرونده یا شماره موبایل ثبت‌شده در داده نمونه).
- مربی‌های نمونه: «حسین احمدی» و «مریم حسینی»؛ مربی اول دو هنرجوی نمونه و مربی دوم یک هنرجوی نمونه دارد.
- مدیر: ورود نمایشی با هر نام دلخواه.
- برای تست ثبت‌نام، از گزینه «ثبت‌نام اولیه هنرجو» در صفحه ورود استفاده کنید. در حالت محلی، پرونده در IndexedDB همین مرورگر ثبت می‌شود.
- برای اختصاص جلسه جدید، با نقش مدیریت وارد شوید، به «برنامه کلاس‌ها» بروید و جلسه را با انتخاب هنرجو و مربی ثبت کنید. سپس با حساب همان هنرجو و مربی وارد شوید تا فقط همان جلسه را ببینید.

### محدودیت مهم
این جداسازی در نسخه فعلی برای تست رابط و جریان کار اعمال شده است؛ انتخاب نقش در صفحه ورود احراز هویت واقعی نیست. داده‌ها روی همان مرورگر/دستگاه قرار دارند و کاربر فنی می‌تواند داده محلی را دستکاری کند. پیش از استفاده واقعی باید OTP، session امن، مجوزهای سمت سرور، محدودسازی پاسخ‌های مربی، ذخیره‌سازی خصوصی اسناد و پشتیبان‌گیری پیاده‌سازی شوند. فایل `backend/API_CONTRACT.md` مرز دقیق APIهای هر نقش را مشخص می‌کند و migration `004_role_specific_access.sql` جدول درخواست ثبت‌نام و تخصیص مربی به هنرجو را می‌سازد.


## نسخه ۰.۹ — فضای اختصاصی هر هنرجو و مربی

### هنرجو
- درخواست ثبت‌نام اولیه از صفحه ورود؛ در نسخه محلی پرونده آزمایشی ساخته می‌شود، در API درخواست پس از احراز شماره همراه در صف بررسی مدیریت قرار می‌گیرد.
- داشبورد وضعیت پرونده، تعداد جلسات اختصاص‌یافته، پیشرفت بر اساس مرحله واقعی پرونده و مانده شهریه را از پرونده همان هنرجو محاسبه می‌کند؛ اعداد ثابت و مشترکِ قبلی حذف شده‌اند.
- تقویم فقط جلساتی را نشان می‌دهد که `studentId` آن‌ها با شناسه حساب فعلی برابر است.
- پرونده، اسناد و سوابق مالی از مسیرهای شخصی استفاده می‌کنند؛ اعلام پرداخت هنرجو تا تأیید مدیریت معلق می‌ماند.

### مربی
- فقط جلسات با `instructorId` برابر شناسه مربی فعلی نمایش داده می‌شود.
- فهرست هنرجویان از تخصیص‌های فعال یا جلسات تخصیص‌یافته ساخته می‌شود؛ اطلاعات هویتی، نشانی کامل، مدارک و مانده مالی در فضای مربی نمایش داده نمی‌شود.
- گزارش جلسه با شناسه مربی فعلی ثبت و هنگام نمایش نیز با همان شناسه فیلتر می‌شود.
- آمار داشبورد مربی از تعداد جلسات تخصیص‌یافته، هنرجویان مرتبط و گزارش‌های خودش محاسبه می‌شود.

### مدیریت
- تنها نقش مدیریت به فهرست کل هنرجویان، پرونده کامل، اسناد همه پرونده‌ها، امور مالی آموزشگاه و برنامه‌ریزی/تخصیص جلسات دسترسی دارد.
- تخصیص یک جلسه، همان برنامه را در فضای هنرجوی مربوط و مربی مربوط قرار می‌دهد.

### تست سریع نقش‌ها در حالت محلی
- هنرجو: «آرمان رضایی» یا «نگار محمدی» یا «پارسا کریمی» یا «هانیه مرادی»؛ همچنین شماره پرونده نمونه.
- مربی: «حسین احمدی» یا «مریم حسینی».
- مدیریت: ورود نمایشی با هر نام.
- مدیریت یک جلسه برای هنرجو و مربی بسازد؛ سپس با همان دو حساب وارد شوید و ببینید جلسه فقط در صفحات همان دو نفر نمایش داده می‌شود.
- گزارش مربی اول در حساب مربی دوم ظاهر نمی‌شود.

### محدودیت امنیتی
این نسخه همچنان پیش‌نمایش محلی است. جداسازی نقش‌ها و اطلاعات برای تست رابط و گردش کار در سمت مرورگر انجام شده؛ این جایگزین احراز هویت و مجوزدهی سمت سرور نیست. برای استفاده واقعی باید OTP، session امن، نقش و مالکیت سمت سرور، فضای خصوصی اسناد، ثبت audit و پشتیبان‌گیری فعال شوند. فایل `backend/API_CONTRACT.md` مرز هر endpoint را شرح می‌دهد.

## رابط کاربری فارسی و پوسته روشن/تاریک
- رابط کاربری فقط به زبان فارسی و با چیدمان راست‌به‌چپ ارائه می‌شود؛ گزینه و منطق تغییر زبان حذف شده است.
- تم روشن و تاریک در صفحه ورود و پنل‌های هنرجو، مربی و مدیریت فعال است.
- انتخاب پوسته در همان مرورگر ذخیره می‌شود و پس از بارگذاری مجدد یا نصب PWA باقی می‌ماند.
- پیام‌های خالی‌بودن یا نامعتبر بودن فیلدها به فارسی نمایش داده می‌شوند؛ پیام پیش‌فرض انگلیسی مرورگر غیرفعال شده است.
- فایل `appearance.js` تنظیمات پوسته و اعتبارسنجی فارسی فرم‌ها را مدیریت می‌کند و در پوسته PWA نیز cache می‌شود.

برای آزمون تنظیمات پوسته و پیام‌های فرم:
```bash
node tests/appearance-smoke.mjs
```


## بازطراحی کامل تم روشن و تاریک

در نسخه جدید، پوسته نمایش به‌صورت سراسری بازطراحی شده است. انتخاب تم از طریق `nasirUiTheme` در مرورگر ذخیره می‌شود و پیش از بارگذاری فایل‌های CSS اعمال می‌شود تا هنگام باز شدن سایت، پرش رنگ بین دو تم رخ ندهد.

- فایل `theme-system.css` لایه اصلی رنگ‌ها و اجزای ظاهری تمام بخش‌ها را مدیریت می‌کند.
- پوسته روشن از زمینه روشنِ خنثی، کارت‌های سفید، رنگ مکمل سبزآبی و جزئیات طلایی استفاده می‌کند.
- پوسته تاریک از پس‌زمینه گرافیتی، سطوح سبزآبی تیره و متن روشن استفاده می‌کند.
- صفحه ورود، منوی کناری، نوار بالا، داشبوردها، فرم‌ها، جدول‌ها، زمان‌بندی، پرونده هنرجو، مدارک، امور مالی، آموزش، گزارش‌ها، تنظیمات، اعلان‌ها و پنجره‌ها از یک سیستم رنگی مشترک پیروی می‌کنند.
- فایل پوسته در حافظه آفلاین PWA نیز ذخیره شده و نام کش برای دریافت نسخه جدید تغییر کرده است.

برای تغییر ظاهر، فایل `theme-system.css` را ویرایش کنید؛ رنگ‌های اصلی هر دو حالت در ابتدای همین فایل در متغیرهای CSS تعریف شده‌اند.

## بازطراحی فرم ثبت‌نام هنرجو و تاریخ شمسی
- فرم ثبت‌نام مدیریت با کارت معرفی، بخش‌بندی بصری، فاصله‌گذاری و فیلدهای هماهنگ با تم روشن و تاریک بازطراحی شد.
- فرم ثبت‌نام اولیه هنرجو نیز با سربرگ اختصاصی و ساختار مرتب‌تر هماهنگ شد.
- تاریخ تولد، تاریخ ثبت‌نام، تاریخ‌های پرداخت، جلسه، آزمون، قرارداد و رویدادهای پرونده در رابط کاربری با تقویم شمسی و ارقام فارسی وارد یا نمایش داده می‌شوند.
- تاریخ شمسی هنگام ذخیره به ISO میلادی تبدیل می‌شود تا سازگاری با API، پایگاه داده و سوابق قبلی حفظ شود.
- تاریخ نامعتبر با پیام فارسی مشخص می‌شود و مانع ارسال فرم خواهد شد.
- نسخه کش PWA برای دریافت این به‌روزرسانی تغییر کرده است.

### انتخاب تاریخ شمسی
تمام فیلدهای تاریخ از تقویم آماده جلالی استفاده می‌کنند. با لمس آیکون تقویم می‌توان ماه را جلو و عقب برد، روز را انتخاب کرد، به تاریخ امروز رفت یا مقدار را پاک کرد. تاریخ نمایشی شمسی و فارسی است و مقدار پنهان فرم به ISO میلادی ذخیره می‌شود تا با API و پایگاه داده سازگار بماند. دکمه تقویم در هر دو پوسته روشن و تاریک همیشه قابل مشاهده و قابل لمس است.


## تاریخ تولد به‌صورت ورود دستی
- فیلد تاریخ تولد در ثبت‌نام اولیه، ثبت پرونده توسط مدیریت و ویرایش مشخصات پرونده، ورودی دستی است و تقویم بازشو یا آیکون تقویم ندارد.
- کاربر فقط عددهای سال، ماه و روز را وارد می‌کند؛ اسلش‌ها پس از سال و ماه به‌صورت خودکار درج می‌شوند (قالب `سال/ماه/روز` مثل `۱۴۰۵/۰۹/۰۳`).
- تاریخ ناقص یا نامعتبر با پیام فارسی مشخص می‌شود و اجازه ثبت نمی‌دهد.
- مقدار نمایشی شمسی است و مقدار مخفی فرم برای سازگاری با API و پایگاه داده به ISO میلادی تبدیل می‌شود.
- سایر فیلدهای تاریخ مانند تاریخ ثبت‌نام، پرداخت، جلسه و آزمون همچنان از تقویم شمسی انتخاب می‌شوند.
